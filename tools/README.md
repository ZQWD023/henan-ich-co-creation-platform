# tools/ —— 「一键启动后端」协议（可选，纯便利功能）

## 这是什么

浏览器有硬性安全限制：**网页（HTML）不能直接启动本地程序**。
所以"点一下 index.html 里的按钮就把后端跑起来"在技术上只有一条官方途径：
注册一个**自定义 URL 协议**（本项目用 `ich://`），由用户点击页面上的链接触发，再由系统调用启动脚本。

```
网页上的 <a href="ich://start">  →  Windows 按注册表找到启动器  →  wscript 调 launcher.js  →  后端启动
```

## 怎么用（只在本机演示时用）

1. **一次性安装**：双击 `tools\安装一键启动.cmd`（会把协议写进当前用户注册表 `HKEY_CURRENT_USER`）。
2. 之后在网页上（离线提示条 / 底部的"后端服务没有启动"提示里）点 **「一键启动后端」**，
   浏览器会弹一次"是否打开 ich"的确认，点「打开」即可。
3. 服务起来后，页面会在 4 秒内**自动探测并刷新**成真实数据。

**卸载**：双击 `tools\卸载一键启动.cmd`（删除 `HKEY_CURRENT_USER\Software\Classes\ich`）。

## 文件说明

| 文件 | 作用 |
|---|---|
| `ich-start.vbs` | 被协议调用的启动器：隐藏窗口执行 `node launcher.js`（ASCII 编码，避免 wscript 把 UTF-8 当 ANSI 解析报错） |
| `安装一键启动.cmd` | 生成 `ich.reg`（自动带上当前绝对路径）并导入 |
| `卸载一键启动.cmd` | 删除协议注册表项 |
| `ich.reg` | 安装时自动生成，可手动双击导入 |

## 为什么不把它当主入口

- **评审机器上没有你的注册表项**，协议不会生效；评委也不会在你电脑上操作。
- 所以主入口仍然是 **`启动网站.bat`**（双击一次即可，等价于 `npm start`），
  协议只是"本机调试/自嗨"的便利，不写进作品功能、不作为卖点。

## 合规说明（如果评委问）

- 赛道规则（作品要求/提交要求/违规处理）里**没有禁止**本地启动后端或提供启动脚本 ——
  前后端分离项目本来就需要一个后端服务，`启动网站.bat` 等价于 `npm start`。
- 我们刻意避开了"偷偷启动、无法关闭、捆绑安装"这类观感很差的形态：
  有明确的安装/卸载脚本、只改当前用户注册表、启动的进程可以随时关窗口或 Ctrl+C 停止。
- 参赛作品的评分看的是 Web 应用本身的 AI 能力与工程质量，启动方式不加分也不减分。
